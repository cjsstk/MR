# 면접 대비 — 프로젝트 전체 소개 (Q7)

> 면접에서 "프로젝트에 대해 전체적으로 설명해 주세요" 질문을 받았을 때 쓰는 스크립트입니다.
> **큰 그림(분산 서버) → 데이터 구조(코드젠) → 내 담당(게임플레이) → 구체 사례** 순으로 좁혀가세요.

---

## 한 문장 요약 (오프닝)
> "C++ 기반 분산 서버와 언리얼 엔진 클라이언트로 만든 **MMORPG**로, 843개의 CSV 데이터 테이블을
> 코드젠으로 서버·클라가 공유하는 **데이터 주도(data-driven) 구조**입니다.
> 저는 주로 **존 서버의 전투·스킬·몬스터 AI·이동 시스템과 인게임 콘텐츠(던전, 길드전)** 를
> 서버·클라 양쪽으로 개발했습니다."

---

## 1. 아키텍처 — "역할별로 서버를 쪼갠 분산 구조"
대규모 동시접속을 감당하기 위해 서버를 역할별로 분리한 멀티 서버 구조입니다.

| 서버 | 역할 |
|------|------|
| **LoginServer** | 초기 로그인 처리 |
| **WorldServer** | 로비/월드 — 인증·채널 관리·존 입장 |
| **ZoneServer** | 실제 게임플레이 존 — 전투·이동·몬스터·아이템 (**주 담당**) |
| **SwitchServer** | 서버 간 라우팅/중계 (인터서버 콘텐츠) |
| **UniversalServer** | 길드·거래소 등 공통 서비스 |
| **common/** | 모든 서버가 공유하는 공통 라이브러리 |

**설명 포인트**
> "플레이어가 많은 게임플레이 부하는 ZoneServer를 여러 개로 분산하고, 로그인·길드·거래소처럼
> 성격이 다른 기능은 별도 서버로 떼어 **독립적으로 확장·배포**할 수 있게 한 구조입니다."

---

## 2. 클라이언트 — "언리얼 엔진 + 커스텀 C++ 모듈"
- **언리얼 엔진** 기반, `Q7`(런타임)·`Q7Editor`(툴) C++ 모듈로 구성.
- 서버가 위치·전투를 계산하는 **서버 권위(server-authoritative)** 방식.
  클라는 서버 결과를 받아 **부드럽게 표현(보간)** 하는 역할.
  (→ 이동 버벅임·채널링 당기기 사례가 여기서 나옴)

---

## 3. 데이터 주도 + 코드젠 — "이 프로젝트의 핵심 강점"
- 게임 데이터(스킬·몬스터·상태이상·아이템 등)는 **843개 CSV → CMS(Content Management System) 테이블**로 로드.
- **Go로 만든 코드젠 툴**이 CSV/프로토콜 정의로부터 enum·구조체·패킷 코드를 자동 생성해
  **C++ 서버와 UE 클라가 같은 소스를 공유**.

**설명 포인트**
> "기획자가 CSV만 수정하면 서버·클라 코드에 일관되게 반영돼 **빌드 없이 콘텐츠를 추가**하고,
> 서버-클라 데이터 불일치를 원천 차단합니다. 제 CC 면역 시스템도 이 구조를 활용해
> 테이블 추가만으로 확장했습니다."

---

## 4. 주요 게임플레이 시스템 (ZoneServer)
- **전투(Combat)** — 데미지·명중/회피·상태이상 판정
- **이동(Movement)** — PhysX / Navigation, 서버 권위 이동 + 어뷰징 검증
- **몬스터 AI** — 비헤이비어 트리 기반 (스킬 콤보·인터벌·타겟팅 노드)
- **스킬 / 상태이상(StatusChange)** — 스킬 콤보, CC(군중제어)·면역, HUD 이펙트
- **아이템 / 전리품 / 퀘스트**
- **던전 콘텐츠** — 권능의 신전, 길드전, 칼레바르의 수레, 금기의 미궁 등
- **길드 / 거래소** — UniversalServer 연계

---

## 5. 나의 역할 (마무리)
> "저는 ZoneServer의 게임플레이 로직과 UE 클라를 **풀스택으로** 담당했습니다. 구체적으로
> ▲보스 스킬 콤보 AI 시스템 설계
> ▲채널링 당기기 같은 신규 전투 기능(서버 계산 + 클라 동기화)
> ▲길드전·권능의 신전 등 대형 콘텐츠 구현
> ▲이동 어뷰징 오탐 같은 라이브 버그의 근본원인 분석·해결
> 을 맡았습니다."
